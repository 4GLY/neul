## 1. 개요 (Executive Summary)

**dfc**는 여러 개발 머신(macOS·Linux)을 **중앙 웹 control plane**에서 선언적으로 관리하는 OSS 클라우드 도구다. 사용자는 웹 UI에서 패키지·dotfiles·시크릿·AI 도구 설정을 선언하고, 각 머신에 설치된 **agent 데몬**이 그 desired state로 reconcile한다.

**핵심 가치 제안:** Nix·home-manager의 *declarative + reproducible* 정신은 유지하되, *빌드 시간·격리·OS별 호환성·인증 풀림*의 부담은 제거한다. 각 OS의 네이티브 패키지 매니저(Homebrew, apt, mise, cargo, pipx 등)를 어댑터로 추상화해 활용한다.

**수익 모델:** 없음. OSS 클라우드 도구. Hosted + self-hosted 모두 1급 시민.

---

## 2. 문제 정의 (Problem Statement)

기존 dotfiles 저장소가 **Nix + home-manager** 기반으로 macOS/Linux를 통합 관리하지만, 다음 불편이 누적되었다:

1. **빌드 시간·디스크·성능** — `drs`(재빌드)가 느리고 `/nix/store` 용량이 지속적으로 증가하며, GC·세대 관리 부담이 크다.
2. **생태계·패키지 동기화** — 최신 패키지가 늦게 들어오고, AI 도구 같은 일부 도구는 nixpkgs에 없거나 오래되어 Homebrew 병행이 필수가 된다.
3. **Darwin/Linux 차이·호환성** — 같은 flake가 두 OS에서 다르게 동작하는 경우가 잦고 `nix-darwin` 특수 이슈가 반복 발생한다.
4. **글로벌 인증 풀림** — Nix가 매번 새로운 store path를 만드는 특성상 일부 도구의 인증·세션이 풀린다.

dfc는 이 네 가지 불만을 **declarative은 유지하되 격리는 포기**하는 방식으로 정면 해결한다.

## 3. 목표·비목표

### 3.1 목표 (Goals)

- 여러 머신의 setup을 중앙 웹에서 선언·관리한다.
- 사용자가 CLI를 거의 만지지 않게 한다. CLI는 페어링·데몬 설치·로그 확인만.
- macOS·Linux 모두 동일한 모델로 다룬다. OS 차이는 어댑터가 흡수한다.
- self-hosted를 1급 시민으로 둔다 (`docker run` 한 줄).
- E2E 암호화로 시크릿을 다룬다. server는 평문을 보지 않는다.
- 보안 우선: server compromise = 모든 머신 RCE 시나리오를 디자인으로 차단한다.

### 3.2 비목표 (Non-Goals)

- 컨테이너 기반 dev environment (Gitpod·Codespaces 대체) — 목적이 다르다.
- 팀·조직 협업 기능 (SSO, RBAC, 감사 export) — MVP 이후 별도 고려.
- 결제·구독 — OSS 도구로 수익화하지 않는다.
- Windows 지원 — 초기 범위에서 제외 (장기 로드맵에서 재검토).
- 시스템 패키지 변경 (`/etc`, `/usr` 수정) — 화이트리스트된 사용자 경로만 다룬다.

## 4. 페르소나·핵심 시나리오

### 4.1 페르소나

**P1. 개인 풀스택 개발자 (1차 사용자)**
- 노트북·서버·VM 등 2~5대 머신을 운영
- 환경 일관성을 원하지만 Nix의 부담은 피하고 싶음
- 자기 데이터를 self-hosted로 둘 수 있길 원함

**P2. OSS 기여자 (2차 사용자)**
- 자기 환경을 dfc로 관리하면서 dfc 자체에도 기여
- self-hosted 인스턴스에서 활용

### 4.2 핵심 시나리오

**S1. 첫 머신 등록**
1. 사용자가 hosted 또는 self-hosted 인스턴스에서 Magic Link로 회원가입.
2. 웹 대시보드에서 페어링 안내.
3. 머신에서 `dfc init` → CLI가 페어링 코드 표시 → 웹에 입력.
4. `dfc agent install` → systemd/launchd 서비스로 등록.
5. 웹에 머신이 "연결됨"으로 나타남.

**S2. 패키지 추가 (웹 중심)**
1. 웹의 패키지 카탈로그에서 `kubectl 1.31` 검색·선택.
2. "어디에 적용할지" 선택: base segment / darwin override / 특정 머신.
3. 변경 즉시 저장 (sudo 필요 없으므로 confirm 모달 없음).
4. agent의 다음 reconcile에서 자동 설치 (보통 즉시 — WebSocket push).
5. 웹에 진행률·결과 표시.

**S3. 기존 dotfile 가져오기**
1. 웹에서 "이 머신에서 가져오기" → 경로 `~/.zshrc`.
2. agent가 파일 읽어 업로드 → base segment에 등록.
3. 다른 머신은 다음 reconcile에서 자동 적용 (default: symlink).

**S4. dotfile 편집**
1. 웹의 CodeMirror 에디터에서 수정.
2. diff 미리보기 → 즉시 저장 (text 편집은 즉시 push 정책).
3. 영향받는 머신 N대에 자동 적용.

**S5. 시크릿 추가 (E2E)**
1. 웹에서 "시크릿 추가" → 키 `GITHUB_TOKEN`, 값 입력.
2. 브라우저가 사용자 master key + 모든 머신의 public key를 recipients로 age 암호화.
3. server는 ciphertext만 받는다.
4. agent가 머신 private key로 복호화 → 환경변수 또는 `~/.config/dfc/secrets/`에 배치.

**S6. 드리프트 대응**
1. 사용자가 머신에서 `brew uninstall kubectl` 실행 (수동 변경).
2. 다음 reconcile에서 agent가 드리프트 감지 → 웹에 표시.
3. 정책에 따라: 자동 복구 (default) 또는 alert-only.

### 5.2 컴포넌트 책임

| 컴포넌트 | 책임 | 기술 |
|---------|------|-----|
| **dfc-server** | REST API, WebSocket hub, 웹 UI 정적 자산 서빙. 단일 Go 바이너리 | Go (chi/echo), embed.FS, SQLite/Postgres driver |
| **dfc-agent** | reconcile 루프, 어댑터 실행, 머신 상태 보고. 사용자 권한 데몬 | Go, exec.Command (no shell), `containerd`-style |
| **dfc CLI** | 페어링·데몬 설치·상태 확인만 (4개 명령) | Go, monorepo 공유 |
| **Web UI** | 머신 대시보드, 프로필 편집, 파일 에디터, diff, 시크릿 추가 | Vite + React + TypeScript, react-query, react-router, shadcn/ui |
| **DB** | 사용자·프로필·세그먼트·리소스·머신·시크릿 메타데이터 | SQLite (default) → Postgres (옵션) |
| **Blob storage** | 파일 콘텐츠 blob | Local FS (default) → S3-호환 (옵션) |

### 5.3 기술 스택 요약

- 서버·CLI·agent: Go 1.22+
- 웹: TypeScript + React 19 + Vite
- DB: SQLite (default, embedded) / Postgres (옵션, env로 활성화)
- Storage: Local FS (default) / S3-호환 (옵션, env로 활성화)
- 빌드: GoReleaser (single binary releases, brew tap 자동)

## 6. 데이터 모델

### 6.1 ER 다이어그램 (텍스트)

```
User ─┬─< Machine ─── activeProfile ──► Profile
      │                                    │
      │                                    ▼
      └─< Profile ─< Segment ─< Resource ─┬─► File ─< FileVersion ─► Blob
                       │                  ├─► Package (spec only)
                       │                  └─► Secret  (ciphertext ref)
                       │
                       └─ match rules: { os, tags, priority }
```

### 6.2 핵심 스키마

```sql
-- 사용자
CREATE TABLE users (
  id           TEXT PRIMARY KEY,    -- ULID
  email        TEXT UNIQUE NOT NULL,
  github_id    TEXT UNIQUE,
  master_pubkey TEXT,                -- age public key (시크릿용)
  created_at   INTEGER NOT NULL
);

-- Magic link
CREATE TABLE magic_links (
  token_hash   TEXT PRIMARY KEY,    -- SHA-256
  email        TEXT NOT NULL,
  expires_at   INTEGER NOT NULL,
  used_at      INTEGER
);

-- 프로필
CREATE TABLE profiles (
  id           TEXT PRIMARY KEY,
  user_id      TEXT NOT NULL REFERENCES users(id),
  name         TEXT NOT NULL,
  created_at   INTEGER NOT NULL
);

-- Segment (base + overrides)
CREATE TABLE segments (
  id           TEXT PRIMARY KEY,
  profile_id   TEXT NOT NULL REFERENCES profiles(id),
  name         TEXT NOT NULL,    -- "base", "darwin", "work-mac"
  match_os     TEXT,             -- 'macos' | 'linux' | NULL
  match_tags   TEXT,             -- JSON array, e.g. ["work"]
  priority     INTEGER NOT NULL  -- base=0, override>0
);

-- Resource (선언적 리소스)
CREATE TABLE resources (
  id           TEXT PRIMARY KEY,
  segment_id   TEXT NOT NULL REFERENCES segments(id),
  kind         TEXT NOT NULL,    -- 'package' | 'file' | 'secret'
  spec         TEXT NOT NULL,    -- JSON, schema는 kind별
  priority     INTEGER NOT NULL,
  created_at   INTEGER NOT NULL
);

-- Files (kind=file 의 콘텐츠 메타)
CREATE TABLE files (
  id                  TEXT PRIMARY KEY,
  resource_id         TEXT NOT NULL REFERENCES resources(id),
  path                TEXT NOT NULL,
  mode                INTEGER NOT NULL,
  current_version_id  TEXT REFERENCES file_versions(id)
);

CREATE TABLE file_versions (
  id           TEXT PRIMARY KEY,
  file_id      TEXT NOT NULL REFERENCES files(id),
  blob_key     TEXT NOT NULL,
  sha256       TEXT NOT NULL,
  size         INTEGER NOT NULL,
  created_at   INTEGER NOT NULL,
  machine_id   TEXT REFERENCES machines(id)
);

-- Secrets (E2E ciphertext)
CREATE TABLE secrets (
  id           TEXT PRIMARY KEY,
  resource_id  TEXT NOT NULL REFERENCES resources(id),
  key          TEXT NOT NULL,        -- "GITHUB_TOKEN"
  ciphertext   BLOB NOT NULL,        -- age encrypted to all recipients
  recipients   TEXT NOT NULL,        -- JSON: list of pubkey IDs
  created_at   INTEGER NOT NULL
);

-- Machines
CREATE TABLE machines (
  id                 TEXT PRIMARY KEY,
  user_id            TEXT NOT NULL REFERENCES users(id),
  name               TEXT NOT NULL,
  os                 TEXT NOT NULL,    -- 'macos' | 'linux'
  arch               TEXT NOT NULL,    -- 'amd64' | 'arm64'
  tags               TEXT,             -- JSON array
  active_profile_id  TEXT REFERENCES profiles(id),
  pubkey             TEXT NOT NULL,    -- agent의 age public key
  last_seen_at       INTEGER,
  paired_at          INTEGER NOT NULL
);

-- Auth tokens
CREATE TABLE auth_tokens (
  token_hash   TEXT PRIMARY KEY,
  user_id      TEXT NOT NULL REFERENCES users(id),
  machine_id   TEXT REFERENCES machines(id),
  expires_at   INTEGER,
  created_at   INTEGER NOT NULL,
  revoked_at   INTEGER
);

-- Pairing codes
CREATE TABLE pairing_codes (
  code         TEXT PRIMARY KEY,
  user_id      TEXT NOT NULL,
  expires_at   INTEGER NOT NULL,
  consumed_at  INTEGER,
  machine_id   TEXT
);

-- Reconciliation log
CREATE TABLE reconciliations (
  id           TEXT PRIMARY KEY,
  machine_id   TEXT NOT NULL REFERENCES machines(id),
  started_at   INTEGER NOT NULL,
  finished_at  INTEGER,
  status       TEXT NOT NULL,    -- 'running' | 'success' | 'partial' | 'failed'
  desired_hash TEXT NOT NULL,
  log          TEXT              -- JSON: per-resource action + result
);

-- Package catalog (검색·매핑용)
CREATE TABLE package_aliases (
  canonical    TEXT NOT NULL,
  manager      TEXT NOT NULL,    -- 'brew' | 'apt' | 'mise' ...
  os           TEXT,             -- NULL = any
  package_id   TEXT NOT NULL,
  PRIMARY KEY (canonical, manager, os)
);
```

### 6.3 Resource spec 예시 (JSON)

```jsonc
// kind=package
{ "name": "kubectl", "version": "1.31", "prefer": ["mise", "brew", "apt"] }

// kind=file
{ "path": "~/.zshrc", "current_version_id": "fv_01HXY..." }

// kind=secret
{ "key": "GITHUB_TOKEN", "secret_id": "sec_01HXY..." }
```

### 6.4 머신 매칭 규칙

머신은 자기 `os`, `tags`로부터 `active_profile_id`의 모든 segment를 다음 규칙으로 평가한다:

1. `segment.match_os`가 NULL이거나 머신의 `os`와 일치
2. `segment.match_tags`가 비어있거나 머신의 `tags`가 모두 포함
3. 위 두 조건을 만족하는 segment들을 `priority` 오름차순으로 정렬
4. 같은 `path`(file) 또는 같은 canonical name(package)이 여러 segment에 있으면 **priority가 높은 게 이긴다**

## 7. API 표면

### 7.1 인증

```
POST /api/auth/magic-link        { email }                   → 메일 전송
GET  /auth/verify?token=...                                  → 302 + 쿠키
GET  /api/auth/github/start                                  → OAuth 시작
GET  /api/auth/github/callback                               → 콜백
POST /api/auth/logout
POST /api/auth/logout-everywhere
```

### 7.2 페어링

```
POST /api/pair/init                                          → { code, expires_at }
POST /api/pair/claim             { code }   [web session]    → 머신 등록, 토큰 발급
GET  /api/pair/poll?code=...                  [CLI]           → 토큰 폴링
```

### 7.3 머신·Agent

```
POST /api/machines/:id/heartbeat          [agent]            → 머신 상태 보고
GET  /api/machines/:id/desired-state      [agent]            → 머신용 합성 desired
POST /api/machines/:id/reconciliation     [agent]            → reconcile 결과 보고
GET  /api/machines/:id/status             [web]              → 마지막 상태·드리프트
DELETE /api/machines/:id                   [web]              → revoke + 토큰 무효
WS   /ws/agent/:machine_id                [agent]            → 변경 알림 push
```

### 7.4 프로필·세그먼트·리소스

```
GET    /api/profiles
POST   /api/profiles                       { name }
PATCH  /api/profiles/:id
DELETE /api/profiles/:id

GET    /api/profiles/:id/segments
POST   /api/profiles/:id/segments          { name, match_os, match_tags, priority }
PATCH  /api/segments/:id
DELETE /api/segments/:id

GET    /api/segments/:id/resources
POST   /api/segments/:id/resources         { kind, spec, priority }
PATCH  /api/resources/:id
DELETE /api/resources/:id
```

### 7.5 파일 blob

```
POST /api/files/upload-url       { sha256, size, content_type }  → { upload_url (presigned PUT), version_id }
POST /api/files/:id/commit       { version_id }                  → 200
GET  /api/files/:id/blob/:version_id                              → 302 (presigned GET)
```

### 7.6 시크릿

```
POST /api/secrets                { key, ciphertext, recipients } → 200
GET  /api/secrets/:key                                            → { ciphertext, recipients }
DELETE /api/secrets/:key
POST /api/secrets/rotate         { key, new_ciphertext, recipients }
```

### 7.7 패키지 카탈로그

```
GET /api/packages/search?q=kubectl                            → [{ canonical, description, aliases }]
GET /api/packages/:canonical                                  → { aliases: { brew, apt, mise, ... }, os_support }
```

### 7.8 감사·이벤트

```
GET /api/events?since=...                                     → 사용자 이벤트 스트림 (alert, drift, failure)
```

## 8. CLI — 최소 명령어

```bash
dfc init             # 페어링 (브라우저 코드 입력)
dfc agent install    # systemd/launchd 서비스 등록
dfc agent status     # 데몬 상태·마지막 reconcile
dfc agent logs       # 트러블슈팅
```

`add`, `apply`, `list`, `profile`, `segment`, `unpair` 등은 **의도적으로 제거**한다. 모든 선언·관리·revoke는 웹에서 수행한다.

CLI 설치:
```bash
curl -fsSL https://get.dfc.sh | sh
# 또는
brew install <org>/tap/dfc
```

## 9. 웹 UI 화면

| 경로 | 핵심 위젯 |
|------|---------|
| `/` | 머신 대시보드 — 머신별 헬스, OS, 마지막 reconcile, 드리프트 카운트, 빠른 액션 |
| `/machines/:id` | 머신 상세 — reconcile 히스토리·로그, 적용 리소스, "capture from this machine", revoke |
| `/profiles` | 프로필 목록·생성 |
| `/profiles/:id` | 프로필 편집 — segment 트리 + 리소스 편집, **변경 시 영향 머신 미리보기** |

## 10. Agent 동작 모델

### 10.1 Adapter 인터페이스

```go
type Adapter interface {
  Name() string
  Available() bool                              // brew --version 등 자가 진단
  Capture(spec ResourceSpec) (State, error)     // 현재 상태 측정
  Diff(desired, current State) Action
  Apply(action Action) error                    // 실행
}

var registeredAdapters = []Adapter{
  &HomebrewAdapter{}, &AptAdapter{}, &MiseAdapter{},
  &CargoAdapter{},    &PipxAdapter{},
  &DotfileAdapter{},  &SecretAdapter{},
}
```

**중요:** 어댑터는 agent 바이너리에 **컴파일 시점에 박혀** 있다. server는 새 어댑터를 동적으로 push할 수 없다. 보안성을 위한 의도적 제약이다.

### 10.2 Reconcile 루프 (의사 코드)

```
loop {
  desired = api.fetchDesiredState()             // GET /machines/:id/desired-state
  current = captureViaAdapters()
  plan    = diff(desired, current)

  api.reportPlan(plan)                          // drift 감지·웹 표시

  for action in plan {
    if action.needsConfirm && !approved {
      api.reportPending(action)
      continue
    }
    result = applyViaAdapter(action)
    api.reportResult(action, result)
  }

  wait for: WebSocket push | 15분 타이머 | 머신 부팅
}
```

### 10.3 통신 모델

- **Outbound HTTPS only** — inbound 포트 ❌. NAT·방화벽 친화.
- **WebSocket persistent connection** — server → agent 변경 알림. 페이로드는 트리거만, 실제 데이터는 별도 GET.
- **연결 끊김** — 자동 재연결 + 백오프. 15분 폴링이 백업.
- **요청 인증** — Bearer 머신 토큰, 24시간 단명, agent가 자동 갱신.

## 11. 보안 7원칙

1. **Server는 명령을 보내지 않는다, desired state만 보낸다**
   - `{ kind:"package", name:"kubectl", version:"1.31" }` → agent의 어댑터가 자체 변환
   - server compromise 시에도 attacker는 임의 명령을 못 실행한다 (어댑터 의미 안의 명령만)

2. **어댑터는 agent에 컴파일 시점 박힘**
   - 새 매니저 지원하려면 agent 업그레이드 필요
   - server는 어댑터를 동적으로 등록·교체 불가

3. **모든 외부 입력 strict validation**
   ```go
   var packageNameRE = regexp.MustCompile(`^[a-zA-Z0-9._@/+\-]+$`)
   var versionRE     = regexp.MustCompile(`^[a-zA-Z0-9.\-_+]+$`)
   exec.Command("brew", "install", validatedName + "@" + validatedVer)  // ✅
   exec.Command("sh", "-c", ...)                                         // ❌ 절대 금지
   ```

4. **경로 화이트리스트 (파일·시크릿 적용)**
   - 허용: `$HOME/**`, `$HOME/.config/**`, `$XDG_CONFIG_HOME/**`
   - 거부: `/etc/**`, `/usr/**`, `/var/**`, `/System/**`, `/Library/**`
   - 경로 정규화 후 검증 (symlink traversal 방지)

5. **시크릿 E2E (age recipients 모델)**
   - 사용자 master keypair + 머신마다 keypair
   - 시크릿은 `age encrypt --recipient master --recipient machine1 --recipient machine2 ...`
   - server는 ciphertext만 저장 (평문 미접근)
   - 새 머신 추가 시: 사용자 master로 모든 ciphertext 재암호화 (새 머신 pubkey 추가)
   - 머신 revoke 시: 모든 시크릿 회전 권장 (UI에서 일괄 회전 액션)

6. **권한 최소화**
   - agent는 사용자 권한 (no sudo by default): `systemd --user`, `launchd LaunchAgents`
   - brew·mise·cargo·pipx는 sudo 불필요
   - apt는 사용자 opt-in으로만 활성 (`agent ALL=NOPASSWD: /usr/bin/apt install ...`)
   - 기본은 sudo 없는 어댑터만 활성

7. **Audit + Revoke**
   - 모든 reconcile 액션 → server audit log + 머신 local journal
   - 머신 revoke 즉시 가능 (토큰 invalidate, 다음 요청부터 401)
   - "logout everywhere" — 사용자의 모든 토큰을 한 번에 무효화

## 12. 하이브리드 Apply 정책

기본은 **즉시 push**, 다음 조건은 **confirm 모달**을 띄운다:

| 변경 유형 | 정책 |
|---------|-----|
| 텍스트 dotfile 편집 | ✅ 즉시 push |
| 패키지 추가 (sudo 없음) | ✅ 즉시 push |
| 시크릿 값 추가 | ✅ 즉시 push |
| 시크릿 회전 (다운스트림 영향) | ⚠️ confirm |
| 패키지 제거 (의존성 영향 가능) | ⚠️ confirm |
| sudo 필요한 변경 (apt 등) | ⚠️ confirm |
| 한 번에 N≥3 머신에 영향 | ⚠️ confirm + per-machine preview |
| 머신 revoke / 시크릿 mass rotation | ⚠️ 2단계 confirm (타입 확인 입력) |

confirm 모달은 `/changes` 큐로 모인다. 사용자는 일괄로 검토·승인할 수 있다.

## 13. 드리프트 감지

agent는 매 reconcile마다 `capture()` 결과를 `desired_state`와 비교한다. 차이 발생 시:

- **Self-managed drift** (default) — 자동으로 desired state로 회복
- **Manual mode** (사용자 선택) — 드리프트만 감지·웹에 알림, 자동 수정 없음. 사용자가 "Adopt this change" 또는 "Revert" 선택
- 정책은 **profile 단위**로 설정 (예: dev 프로필은 self-managed, work 프로필은 manual)

## 14. 실패 처리

**continue-on-error**가 기본:

```
plan: [
  install kubectl@1.31,        # 성공
  install obscure-pkg@2.0,     # 실패
  apply ~/.zshrc,              # 성공
  set secret GITHUB_TOKEN      # 성공
]
```

한 리소스 실패가 나머지를 막지 않는다. 실패 리소스는 웹에 ❌로 표시되고 다음 reconcile에서 재시도. **3회 연속 실패 시** 자동 재시도 중단 + 사용자 알림.

치명적 실패(예: 모든 어댑터 비가용)는 reconciliation을 abort하고 머신을 "degraded" 상태로 표시.

## 19. 결정된 사항

## 20. 미결정·열린 질문

- **라이선스 최종 결정** — Apache-2.0을 제안했으나 최종 확정 필요. MIT·MPL-2.0·AGPLv3 등 대안 검토 가능.
- **GitHub 조직명·프로젝트명·도메인** — `<org>`·`dfc.sh`·`get.dfc.sh` 등은 모두 placeholder. 실제 이름은 미정.
- **사용자 master key 보관** — 브라우저 localStorage + 패스프레이즈 봉인을 기본으로 하되, 분실 시 복구 흐름이 필요한가? 시크릿을 잃는 게 default인가, 복구 절차를 제공하는가?
- **무료 hosted tier 한도** — 머신 3대·파일 100MB가 적절한지 운영 시작 후 측정 필요.
- **WebSocket 대체 폴백** — 일부 폐쇄망에서 WebSocket 차단 시 long-polling 자동 폴백 구현 필요 여부.
- **카탈로그 데이터 출처** — `package_aliases` 테이블을 어디서 채울지 (수작업? 자동 크롤링? 커뮤니티 기여?). MVP는 수작업 + 사용자 기여 PR 모델로 시작 권장.
- **AI 도구 설정 머지의 시맨틱** — claude/codex/gemini 각각의 settings.json/agents.toml은 깊은 머지가 필요한데, 머지 충돌 시 정책은? (last-write-wins? 사용자 수동 머지? 우선순위 segment 룰 활용?)

## 21. 용어 사전

| 용어 | 정의 |
|------|------|
| **Profile** | 사용자가 만든 dotfiles "워크스페이스". 하나의 사용자는 여러 프로필 가능 (예: personal, work) |
| **Segment** | 프로필 안의 매칭 룰 단위. base(0) + override(>0)로 priority를 가진다 |
| **Resource** | segment에 속한 선언적 항목. kind = package / file / secret |
| **Desired State** | 머신에 적용되어야 할 리소스의 합성된 최종 형태. server가 머신의 os·tags 기준으로 계산 |
| **Capture** | agent가 현재 머신 상태를 측정해 desired state와 비교 가능한 형태로 만드는 작업 |
| **Reconcile** | desired state와 current state를 비교해 차이를 좁히는 actions를 실행하는 루프 |
| **Drift** | reconcile 사이 머신에서 수동 변경이 발생해 current가 desired와 어긋난 상태 |
| **Adapter** | 특정 패키지 매니저 또는 리소스 종류와 통신하는 agent의 모듈 |
| **Recipients (age)** | 시크릿 ciphertext를 복호화할 수 있는 공개키 목록 (사용자 master + 모든 머신) |
